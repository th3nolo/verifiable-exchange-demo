# D implementation API available to A and B

The code is in `services/src/ledger.rs` and `services/src/matcher/funded.rs`.

B: `MatcherState::ledger_snapshot() -> LedgerSnapshot`, `ledger_canonical_bytes() -> Vec<u8>`, `restore_ledger(snapshot) -> Result<(), LedgerError>` are implemented. Restore after book/cursor reconstruction and before root verification. `Ledger::from_snapshot` verifies per-asset conservation against config funding and the exact reserved totals. `restore_ledger` additionally requires the cursor and every open OrderRow to agree with the snapshot. Version = 1, asset_scale = 1000. All structs derive serde with deny_unknown_fields. Canonical bytes are compact JSON of sorted, typed fields; length/domain/version framing belongs to B. No new root or schema in D.

Fields in LedgerSnapshot: version, mode (synthetic_legacy / funded_simulation), asset_scale, config (markets, funding, explicit fee_units=0), last_sequence, balances (account,asset,available,reserved), reservations (order_id,account,symbol,side,limit_cents,remaining_tenths,asset,units). Funding lists normalize order; duplicates are refused. Each account/asset total is bounded by i64; cross-account conservation is measured in i128. No arbitrary credit/deposit method.

A: `Ledger::stage_reserved_fills(fills: impl IntoIterator<Item=(OrderId,OrderId,i64,i64)>) -> Result<Ledger,LedgerError>` accepts tuples (maker,taker,price cents,qty tenths) from the same immutable plan. Clone ledger and call reserve(id,account,symbol,side,effective_limit,quantity) on that clone, then feed `plan.fills().iter().map(|fill| (fill.maker_order, order.id, fill.price_cents, fill.qty_tenths))`. Stage applies ALL fills cumulatively; same accounts/assets combine before checks. Discard clone on any rejection. Commit staged ledger with A's accepted execution plan. In standalone D preflight also stages positions and all fills, then actual loop calls atomic settle_fill BEFORE changing maker qty/positions/trades. Integration should use A's same FOK plan and remove duplicate FOK scan. Non-FOK currently preflights full funded command as well (an arithmetic error rejects the whole funded command).

B/integrator startup: CLI --start-matcher now requires explicit --ledger-mode; old CLI callers/tests/scripts must add --ledger-mode synthetic-legacy. --ledger-mode funded-simulation requires --funding JSON. `start_matcher_with_ledger(options, Ledger)` is new, old Rust start_matcher(options) is a compatibility synthetic wrapper. Temporarily funded SQLite startup fails closed; B must replace this guard with persisted config equality/restore hooks once root/schema are wired. Feed reset reuses the explicit genesis config for its NEW run; recovery of the same run must use snapshot, never funded(config) again.

Expose GET /balances as complete LedgerSnapshot, /market reports ledger_mode and asset_scale. Funded cash/base balances are independent of existing /positions PnL. Canonical encoding is not a promise that the standalone D state_root commits to it; B integration is required before publication.

Final FOK commit hook: BookAndTrades.ledger_plan_committed = true ONLY when A's SAME complete FokPlan has already produced and committed its staged ledger. commit_fill must skip per-fill ledger.settle_fill in this case; this removes fallible monetary arithmetic after first FOK execution effect and prevents double settlement. For non-FOK set false and settle each fill before position/book/TradeRow mutations. Standalone D sets false after full funded preflight; integration consumes A's plan, commits staged funds, and selects true.

B canonical-current requirement: build execution_state() by inserting `ledger-v1` = self.ledger_canonical_bytes() into a fresh extensions map at each root/batch construction. Never keep a stale copy after message/cancel/delist. Restore decoded LedgerSnapshot from extension after book/cursor construction, BEFORE root comparison. Unknown ledger version/scale/mode or incompatible obligations is an error. `replaying_funded_simulation(session, config)` is available for same-genesis replay; never replay funded claims through `replaying()` synthetic engine.
