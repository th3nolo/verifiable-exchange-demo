# D: spot simulation ledger integration contract (2026-10-03)

Implementation available. No custody or deposit/RPC integration. Asset units are **thousandths of one asset**, consistently for every asset; base quantity tenths becomes `qty_tenths * 100`, quote cash mills is `price_cents * qty_tenths`. Explicit config maps each symbol to independent `base_asset` and `quote_asset`; shared assets and self-match use the same account/asset balance.

Public API in `ledger.rs`: `Ledger::synthetic_legacy()`, `Ledger::funded(config)`, `reserve(order_id, account, symbol, side, effective_limit_cents, qty_tenths)`, `settle_fill(maker_order, taker_order, price_cents, qty_tenths)`, `release(order_id)`, `snapshot()`, `from_snapshot(snapshot)`, `canonical_bytes()`, `validate_obligations(open OrderRow slice)`, `finish_sequence(sequence)`. Snapshot contains explicit mode, deterministic genesis funding/config, all available/reserved balances, active obligations and applied sequence. Fees are explicitly zero. Synthetic carries no balances or reservations.

A hook: `BookAndTrades` receives `&mut Ledger`; after checked position computation and BEFORE maker/book/trade mutation call atomic `settle_fill`. For FOK validate ledger over the SAME complete fill plan as positions: clone/stage ledger once, settle every planned fill on the clone, then commit together with plan; do not preflight only the first fill. D standalone matcher will prepare its funded full-command plan before mutation, A/integrator should unify the plan. Reserve after effective bounds/self-trade validation and before any first execution effect. Release taker remainder for IOC/failed FOK/overflow and cancelled/delisted maker IDs once.

B hook: own snapshot/root versioning. Commit `LedgerSnapshot` in same transaction as counters/book/claim; include `ledger.canonical_bytes()` as a length-framed payload in the new state root, restore through `Ledger::from_snapshot` and compare obligations to open rows. Do not change legacy roots silently. Constructor config cannot be replaced on restart. D will not implement root/schema. CLI/API hookup will make mode explicit; durable funded startup must fail closed until B persistence is connected.

Implemented exact-plan boundary: `Ledger::stage_reserved_fills` consumes (maker,taker,price_cents,qty_tenths) tuples mapped directly from A's `FokPlan::fills()`. Commit its returned ledger with the immutable FOK execution plan; set `BookAndTrades.ledger_plan_committed=true` to skip per-fill monetary recomputation/double settlement. Non-FOK uses false and atomic per-fill settlement before book changes. See `D-staging-contract.md` for the complete integration checklist.

B's execution payload key is `extensions["ledger-v1"]`. Compute bytes from the current ledger at each root/commit, restore ledger before comparing root, and keep persisted config/mode on recovery. Snapshot constructors and API reads issue no funding. `MatcherState::replaying_funded_simulation(session, config)` selects deterministic funded replay.
